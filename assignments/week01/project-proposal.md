# 학기 프로젝트 제안서

## 1. 프로젝트 개요

### 프로젝트명

**GROUP-RIDE: 이동수단별 그룹 위치 공유 및 실시간 경로 안내 서비스**

- 프로젝트 분야: 웹 개발 · 위치 기반 서비스 · 실시간 데이터 처리
- 프로젝트 유형: 모바일 웹 기반 그룹 이동 지원 서비스
- 개발 형태: 모바일 웹 서비스
- 핵심 기술: React, TypeScript, Supabase, PostgreSQL
- 프로젝트 진행 단계: 1단계 UI 프로토타입 완료, 2단계 데이터베이스 및 인증 연동 진행 예정

### 프로젝트 소개

GROUP-RIDE는 서로 다른 이동수단을 이용하는 사람들이 하나의 그룹에 모여 위치와 이동 상황을 공유하고, 각자의 이동수단에 맞는 경로 안내를 받을 수 있도록 지원하는 모바일 웹 서비스이다.

사용자는 자동차, 오토바이, 도보, 대중교통 중 하나를 선택하거나 여러 이동수단이 함께하는 혼합 방에 참여할 수 있다. 각 참여자는 공통 목적지를 기준으로 자신의 이동수단에 적합한 경로 안내를 받으며, 같은 방의 참여자들은 지도에서 서로의 위치, 이동 상태, 남은 거리 및 도착 예정 시간을 확인할 수 있다.

또한 경로 이탈 감지 및 재탐색, 실시간 속도 표시, 사용자 프로필과 차량 정보 관리 등의 기능을 제공한다. 백엔드는 Supabase를 활용하여 사용자 인증, 그룹 방, 참여자, 위치 및 경로 데이터를 관리하며, 방별 접근 권한을 적용해 허가된 참여자끼리만 위치 정보를 공유하도록 설계한다.

## 2. 문제 정의

친구나 지인들이 함께 이동할 때 서로 다른 이동수단을 이용하거나 출발 위치가 다르면 일행의 현재 위치와 도착 예정 시간을 파악하기 어렵다. 특히 자동차, 오토바이, 도보 및 대중교통은 이동 가능한 경로와 이동 속도가 서로 다르기 때문에 하나의 경로만으로 모든 참여자의 이동 상황을 관리하기 어렵다.

일반적인 위치 공유 서비스는 참여자의 위치를 확인하는 데 초점을 맞추는 경우가 많으며, 그룹 방 관리와 이동수단별 경로 안내, 경로 이탈 시 재탐색, 참여자별 도착 예정 정보 등을 통합적으로 확인하려면 여러 서비스를 함께 사용해야 할 수 있다.

이에 본 프로젝트는 그룹 방을 중심으로 위치 공유와 내비게이션 기능을 통합한 모바일 웹 서비스를 개발하고자 한다. 참여자는 하나의 목적지를 공유하면서 각자의 이동수단에 맞는 경로를 따라 이동하고, 동일한 방에 참여한 일행의 위치와 이동 상태를 한 화면에서 확인할 수 있다.

또한 위치, 경로, 속도 및 도착 예정 시간은 개인정보 보호를 고려해 방 단위로 접근을 제한하고, 사용자 인증과 데이터베이스 권한 검증을 통해 허가되지 않은 접근을 방지하고자 한다.

## 3. 프로젝트 목표

1. 이동수단별 그룹 방 생성 및 참여 기능을 구현한다.
2. 여러 이동수단이 하나의 방에서 함께 이동할 수 있는 혼합 방을 지원한다.
3. 동일한 방에 참여한 사용자끼리 실시간 위치와 이동 상황을 공유할 수 있도록 한다.
4. 참여자별 이동수단에 적합한 경로 안내와 경로 이탈 시 재탐색 기능을 구현한다.
5. Supabase를 활용해 사용자 인증, 그룹 정보, 참여자 및 위치 데이터를 관리한다.
6. 방별 데이터 접근 권한을 적용해 위치 정보와 이동 관련 데이터를 안전하게 보호한다.
7. GitHub를 활용해 개발 과정과 기능별 작업 이력을 체계적으로 관리한다.

## 4. 핵심 기능 3개

### 기능 1. 이동수단별 그룹 방 생성 및 관리

사용자가 이동 목적에 맞는 그룹 방을 생성하거나 기존 방에 참여할 수 있도록 한다.

- 자동차, 오토바이, 도보, 대중교통별 방 목록 제공
- 여러 이동수단을 허용하는 혼합 방 생성
- 방 이름, 설명, 대표 이미지 및 최대 참여 인원 설정
- 공개 방과 비공개 방 구분
- 초대 코드 생성, 확인 및 재발급
- 방 미리보기 후 참여 여부 결정
- 방장 권한 관리 및 참여자 내보내기
- 방 퇴장, 방장 권한 이전 및 방 종료
- 혼합 방에서 참여자의 이동수단 선택 및 변경

공개 방은 서비스 내 목록에서 검색할 수 있도록 하고, 비공개 방은 초대 코드나 승인 절차를 통해서만 참여할 수 있도록 한다. 방에 입장하기 전에는 해당 방의 참여자 위치나 경로 정보를 공개하지 않는다.

### 기능 2. 실시간 그룹 위치 공유 및 이동 현황 확인

같은 방에 참여한 사용자들의 위치와 이동 상태를 지도에서 확인할 수 있도록 한다.

- 사용자의 위치 공유 시작 및 중지
- 같은 방 참여자의 실시간 위치 표시
- 참여자별 현재 속도 및 평균 속도 표시
- 이동 중, 정차 중, 도착, 위치 업데이트 지연 등의 상태 표시
- 참여자별 남은 거리, 남은 시간 및 도착 예정 시각 표시
- 참여자 목록과 지도 마커 연동
- 참여자별 위치 갱신 시각 표시
- 방 퇴장 및 공유 중지 시 위치 정보 전송과 표시 중단

위치 공유는 사용자가 위치 권한을 허용하고 직접 공유를 시작한 경우에만 작동하도록 한다. 위치 정보가 일정 시간 이상 갱신되지 않으면 이전 위치를 실시간 위치처럼 표시하지 않고, 지연 또는 확인 불가 상태를 표시한다.

### 기능 3. 이동수단별 실시간 경로 안내 및 재탐색

공통 목적지를 기준으로 참여자별 이동수단에 적합한 경로와 이동 안내를 제공한다.

- 목적지 검색 및 설정
- 참여자별 이동수단에 맞는 경로 계산
- 지도에 참여자별 경로선 표시
- 턴바이턴 방식의 다음 행동 안내
- 목적지까지의 남은 거리, 남은 시간 및 도착 예정 시각 표시
- 경로 이탈 감지 및 현재 위치 기준 재탐색
- 목적지 도착 여부 확인
- 이동수단 변경 시 경로 재계산

자동차와 오토바이, 도보 및 대중교통은 서로 다른 경로 조건을 적용한다. 실제 경로 안내는 선정한 지도 SDK와 길찾기 API의 지원 범위에 따라 구현한다. 특히 오토바이 경로와 대중교통 환승 안내는 API 지원 여부를 확인한 후 적용하며, 지원되지 않는 기능을 실제 제공 기능처럼 표시하지 않는다.

## 5. 부가 기능

### 5.1 사용자 프로필 및 이동수단 정보 관리

- 닉네임, 프로필 사진 및 자기소개 설정
- 프로필 테마 색상과 프레임 설정
- 자동차 및 오토바이의 제조사, 모델명, 별명 및 사진 등록
- 한 사용자당 여러 이동수단 등록
- 도보 관련 메모 및 대중교통 노선 정보 입력
- 프로필 변경 사항을 참여자 목록과 지도에 반영

차량 번호와 같은 민감 정보는 본인만 조회할 수 있도록 별도로 관리한다.

### 5.2 그룹 채팅

그룹 채팅은 위치 공유와 길 안내 기능을 안정적으로 구현한 이후 추가 기능으로 개발한다. 전화 통화 기능은 초기 개발 범위에서 제외한다.

## 7. 시스템 구성 및 데이터 설계

### 7.1 시스템 구성

GROUP-RIDE는 모바일 웹 클라이언트와 Supabase 백엔드, 외부 지도 및 길찾기 서비스로 구성한다.

1. 사용자가 웹사이트에 접속해 로그인한다.
2. 이동수단을 선택하고 그룹 방을 생성하거나 참여한다.
3. Supabase가 사용자 인증과 방별 접근 권한을 확인한다.
4. 사용자가 위치 공유를 시작하면 위치 데이터가 전송된다.
5. 같은 방의 참여자는 실시간으로 위치와 이동 상태를 확인한다.
6. 목적지가 설정되면 참여자별 이동수단에 맞는 경로를 계산하고 안내한다.
7. 위치나 목적지가 변경되면 이동 진행 상황을 갱신하고 필요할 경우 경로를 재탐색한다.

### 7.2 주요 데이터 테이블

| 테이블 | 주요 데이터 |
|---|---|
| `users` | 사용자 ID, 닉네임, 프로필, 기본 이동수단 |
| `vehicles` | 사용자별 차량 정보 및 이동수단별 등록 정보 |
| `vehicle_private` | 본인만 조회할 수 있는 차량 번호 등 민감 정보 |
| `groups` | 방 이름, 공개 여부, 허용 이동수단, 초대 코드 해시, 목적지 |
| `group_members` | 방별 참여자, 역할 및 해당 방에서 사용하는 이동수단 |
| `live_locations` | 방·사용자별 최신 위치, 속도, 방향 및 위치 갱신 시각 |
| `member_routes` | 이동수단, 경로, 다음 안내, 남은 거리 및 경로 상태 |
| `trip_stats` | 위치 공유 시작 이후 이동 거리와 경과 시간 |

실제 테이블 구조와 컬럼은 개발 과정에서 확정하며, 데이터베이스의 무결성과 접근 권한을 고려해 설계한다.

### 7.3 보안 및 개인정보 보호

위치 정보는 서비스의 핵심 데이터이므로 화면에서 숨기는 것만으로 보호하지 않고, 서버와 데이터베이스에서도 접근을 제한한다.

- Supabase Auth를 통한 사용자 인증
- Row Level Security(RLS)를 활용한 데이터 접근 제어
- 본인 위치 데이터의 등록 및 수정 권한 검증
- 같은 방에 참여한 사용자만 해당 방의 위치와 경로를 조회하도록 제한
- 비공개 방의 존재 및 내부 정보 노출 방지
- 초대 코드의 해시 저장과 서버 측 검증
- 초대 코드 반복 대입 시도 제한
- 방 퇴장, 강제 퇴장 및 방 종료 시 실시간 구독 해제
- 차량 번호 등 민감 정보의 별도 접근 제어
- 다른 방의 ID를 임의로 입력해도 해당 방의 데이터를 조회할 수 없도록 서버 측 권한 검증

위치 공유는 자동으로 시작하지 않으며, 사용자가 중지하거나 방에서 퇴장하면 추가 위치 전송을 중단한다. 다시 접속한 경우에도 사용자의 명시적인 동의 없이 위치 공유를 자동 재개하지 않는다.

| 8주차 | 방장 권한, 참여자 관리 및 방 종료 구현 | 방 관리 권한 기능 |

| 10주차 | 실제 지도 SDK 연결 및 위치 권한 처리 | 지도 및 위치 수집 기능 |
| 11주차 | 방 내부 실시간 위치 공유 및 상태 표시 | 실시간 그룹 지도 |
| 12주차 | 목적지 검색 및 이동수단별 경로 API 연결 | 실제 경로 안내 기능 |
| 13주차 | 경로 이탈 감지, 재탐색 및 도착 상태 구현 | 경로 안내 개선 기능 |
| 14주차 | 프로필·이미지 업로드 및 부가 기능 구현 | 프로필 관리 기능 |
| 15주차 | 통합 테스트, 보안 점검 및 오류 수정 | 테스트 결과 및 개선 내역 |
| 16주차 | 최종 검수, 문서화 및 발표 준비 | 최종 서비스 및 발표 자료 |

※ 위 일정은 16주 개발 계획 초안이다. 실제 수업 일정과 개발 속도에 따라 조정하며, 핵심 기능의 완성도를 우선한다. 지도 및 길찾기 API의 선정 결과에 따라 10~13주차의 작업 순서가 달라질 수 있다. 그룹 채팅은 핵심 기능이 안정화된 경우에만 추가한다.

## 11. 현재 개발 현황 및 향후 계획

### 완료된 작업

- 이동수단 선택 화면
- 방 목록, 방 생성, 초대 코드 입력 및 방 미리보기 화면
- 그룹 지도와 참여자 목록 화면
- 프로필 편집 및 방 관리 화면
- 혼합 방과 이동수단별 선택 구조
- 샘플 도로망 기반 경로 안내 프로토타입
- 테스트 주행 및 샘플 참여자 시뮬레이션

### 현재 프로토타입의 한계

- 실제 회원가입 및 로그인 기능이 연결되지 않았다.
- 실제 서버 및 데이터베이스가 연결되지 않았다.
- 방과 참여자 데이터는 모의 서버를 통해 브라우저 내부에서 처리된다.
- 위치 공유와 권한 검사는 실제 서비스 수준의 보안 기능이 아니다.
- 지도와 경로는 샘플 도로망을 사용하므로 실제 도로 및 교통 상황과 다를 수 있다.
- 대중교통 및 오토바이 경로는 실제 API의 지원 범위를 확인해야 한다.

### 향후 개발 방향

첫 번째 단계에서 제작한 UI 프로토타입을 유지하면서 Supabase 인증과 데이터베이스를 연결한다. 이후 그룹 방 관리, 접근 권한 및 실시간 위치 공유를 구현하고, 실제 지도와 길찾기 API를 연동한다. 핵심 기능을 통합한 뒤 보안 검증과 사용성 테스트를 진행하여 최종 서비스를 완성한다.
